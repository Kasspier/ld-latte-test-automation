# LD LATTE · Telegram-бот с динамическим меню

Решение задачи №1: n8n при каждом `/start` читает актуальный каталог PostgreSQL и формирует inline-кнопки для всех активных услуг. При выборе перечитывает услугу по ID и отвечает её текущим названием. Количество и подписи кнопок не заданы в workflow вручную.

## Что подготовлено

- `workflow/LD-LATTE-menu.json` — импортируемый workflow без секретных ключей.
- `db/01-catalog.sh` — структура и девять вымышленных услуг; изначально активны две.
- `compose.yaml` — отдельные контейнеры n8n, PostgreSQL и транспорта Telegram. Образы зафиксированы по digest.
- `src/domain.mjs` — логика, которую генератор встраивает непосредственно в Code-узлы n8n.
- `src/relay.mjs` — только транспорт: Telegram long polling → защищённый webhook n8n → отправка готовых запросов в Telegram.
- `scripts/catalog.mjs` — изменение каталога для демонстрации.
- `docs/DEMO.md`, `docs/ARCHITECTURE.md`, `docs/VERIFICATION.md` — показ, устройство и проверенные результаты.

## Запуск с нуля

Нужны Docker Desktop с Linux containers, Docker Compose и Node.js 24+ для подготовительных команд и тестов. Подписка n8n Cloud, Google Sheets и платный хостинг для этого локального варианта не нужны.

```powershell
cd ld-latte-telegram
npm.cmd run setup
```

После распаковки архива выполняйте команды из папки `ld-latte-telegram`. Подготовка создаёт `.env` и `.private/credentials.local.json` с локальными паролями и секретом webhook. Повторный запуск сохраняет уже созданные значения. **Не меняйте пароли и N8N_ENCRYPTION_KEY после создания Docker volumes без отдельной процедуры смены доступа.**

1. В Telegram откройте настоящий **@BotFather**, отправьте `/newbot`, выберите название и свободный username, заканчивающийся на `bot`.
2. Вставьте выданный токен в локальный `.env`, после `TELEGRAM_BOT_TOKEN=`. Без кавычек и пробелов. В чат или репозиторий его не отправляйте.
3. При желании ограничьте доступ к боту: `ALLOWED_USER_IDS=123456789,987654321`. Пустое значение разрешает любые личные чаты; группы и каналы не обрабатываются.
4. Выполните:

   ```powershell
   docker compose up -d
   docker compose ps
   ```

5. Откройте **http://127.0.0.1:5678**. При первом посещении n8n предлагает создать локального владельца: заполните форму самостоятельно. Workflow уже импортирован и опубликован; откройте **LD LATTE — dynamic Telegram services**.
6. Откройте своего бота в Telegram и отправьте `/start`. Должны появиться две inline-кнопки. Нажмите каждую — бот отправит название выбранной услуги.

Если контейнеры уже запущены, а токен добавлен после запуска:

```powershell
docker compose up -d --force-recreate telegram-relay
docker compose logs --tail 20 telegram-relay
```

Токен в выводе relay не печатается. Не публикуйте вывод `docker compose config` или полный `docker inspect`: в них могут оказаться переменные с секретами.

## Где это работает

Всё локальное приложение запускается **в Docker на вашем компьютере**. Редактор n8n доступен только через `127.0.0.1:5678`. PostgreSQL не публикует порт на хост. Бот общается с сервером Telegram исходящими HTTPS-запросами: проброс портов в интернет и публичный HTTPS-туннель не нужны.

Бот работает, пока включён компьютер, запущен Docker и есть интернет. При закрытии браузера бот продолжает работать. После остановки Docker он перестаёт отвечать; услуги и workflow остаются в volumes.

```powershell
docker compose stop
docker compose start
```

Не используйте `docker compose down -v` для обычной остановки: эта команда удалит данные volumes.

## Редактирование услуг и демонстрация

```powershell
npm.cmd run catalog -- list
npm.cmd run catalog -- count 2
npm.cmd run catalog -- count 5
npm.cmd run catalog -- count 9
npm.cmd run catalog -- count 0
```

После каждой команды `count` отправляйте **новую `/start`**. Уже отправленное меню не меняется само — это соответствует ТЗ. Подробные команды изменения и сценарий сдачи: [docs/DEMO.md](docs/DEMO.md).

## Проверка

```powershell
npm.cmd test
npm.cmd run test:integration
```

Интеграционная проверка использует запущенные настоящие n8n и PostgreSQL, передаёт синтетические Telegram updates в webhook и проверяет сформированные сообщения. Она временно меняет только вымышленный каталог этого проекта и восстанавливает его в `finally`. Не выполняйте её параллельно с редактированием/демонстрацией каталога. Реальные сообщения в Telegram этот тест не отправляет.

Полный показ в настоящем Telegram выполнен: 2/5/9 кнопок, выбор разных услуг, переименование, добавление, отключение, удаление и пустой каталог. [HTML-отчёт со снимками](output/TELEGRAM-DEMO.html) открывается без интернета. Изображения находятся рядом в папке `output/telegram`; при передаче отчёта сохраняйте эту папку вместе с HTML. Автоматические проверки: 14/14 тестов и 12/12 интеграционных сценариев. Подробности — [VERIFICATION.md](docs/VERIFICATION.md).

## Что передать при сдаче

1. Экспорт `workflow/LD-LATTE-menu.json` и исходники проекта, включая relay и compose, без `.env`, `.private` и содержимого Docker volumes.
2. [Описание таблицы](docs/ARCHITECTURE.md) и тестовых записей.
3. Эту инструкцию запуска и [план показа](docs/DEMO.md).
4. Ссылку на тестового бота: [@ld_latte_tested_bot](https://t.me/ld_latte_tested_bot) и [результаты полного показа](output/TELEGRAM-DEMO.html). Бот доступен, пока включён локальный Docker владельца.

Готовый комплект для передачи: `delivery/LD-LATTE-Telegram.zip`. В архив включены исходники, экспорт, инструкции и доказательства проверки; локальные секреты и приватные снимки исключены. На новой машине потребуется токен собственного тестового бота.

Экспорт workflow содержит только ссылки на n8n credentials. На новой машине `npm run setup` и старт контейнера создают и импортируют credentials автоматически. В существующем стороннем n8n нужно вручную привязать PostgreSQL read-only credential и Header Auth credential и настроить relay; один JSON без этих компонентов не является самостоятельным Telegram-клиентом.

## Известные ограничения

- Только личные чаты; меню не оформляет заказы и не собирает заявки — этого нет в задаче №1.
- Старые кнопки не перерисовываются автоматически; выбранная услуга всегда перечитывается из базы.
- При редком сбое между успешной отправкой Telegram и сохранением offset после перезапуска сообщение может повториться. Гарантия exactly-once не заявляется.
- Relay не удаляет чужой Telegram webhook: для тестирования нужен отдельный бот. Не запускайте два polling-процесса с одним токеном.
- n8n использует внутренний JavaScript runner для локального тестового проекта. Этот режим помечен n8n как устаревающий; для production нужно отдельно настроить внешний runner. Python-узлы не используются.
- Первый импорт выполняется один раз. Изменение каталога никогда не требует повторного импорта. При изменении кода workflow см. процедуру в [ARCHITECTURE.md](docs/ARCHITECTURE.md).
