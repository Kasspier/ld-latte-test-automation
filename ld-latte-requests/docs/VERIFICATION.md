Данные двух тестовых аккаунтов сохранены только в исключённом из Git `postman/private.local.json`. Они не относятся к реальным сотрудникам. В базе оставлены две заявки Postman и одна заявка браузерной проверки. Автоматическое удаление не выполнялось: пользовательское удаление не предусмотрено ТЗ.

Повторный прогон с существующими аккаунтами пропустит 2 запроса регистрации, выполнит остальные запросы и создаст 2 новые тестовые заявки. Для независимой проверки регистрации используйте пустые `email_a/email_b` в отдельном окружении при выключенном Confirm email.

## Что не проверялось

- Доставка SMTP и ссылки подтверждения: этот механизм временно выключен.
- Автоматическое обновление cookie после длительного простоя; прямой refresh Supabase проверен.
- Браузерный сценарий обрыва соединения в середине сохранения. Дедупликация повторного запроса проверена через API.
- Публичный HTTPS-хостинг, внешний Git-репозиторий и ссылки для передачи работодателю.

Перед публикацией следует вернуть подтверждение почты, настроить отправителя и пройти отдельную проверку email-процесса. Аккаунты, созданные при отключённом подтверждении, не становятся неподтверждёнными автоматически после включения этой настройки.
