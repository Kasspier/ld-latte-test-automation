# API

Все адреса относительны к URL приложения. Ответы JSON с `Cache-Control: no-store`. Запись требует `Content-Type: application/json`; браузерный Origin должен совпадать с адресом приложения.

## Авторизация

| Метод и путь            | Тело / результат                                                              |
| ----------------------- | ----------------------------------------------------------------------------- |
| `POST /api/auth/signup` | `{email,password}` → 201 `{user,confirmationRequired,message}`                |
| `POST /api/auth/login`  | `{email,password}` → 200 `{user:{id,email}}`; сессия в HttpOnly cookie        |
| `GET /api/auth/session` | Cookie или Bearer → 200 `{user:{id,email}}`                                   |
| `POST /api/auth/logout` | `{}` → 200 `{ok:true}`; завершает cookie-сессию, Bearer здесь не используется |

Email нормализуется к нижнему регистру, пароль 8–128 символов без изменения пробелов. При включённом подтверждении почты signup возвращает `user:null`, `confirmationRequired:true`: нужно подтвердить адрес и войти. При повторной регистрации Supabase может скрывать факт существования адреса; сообщение не гарантирует создание нового пользователя.

Для Postman Bearer-токены можно получить непосредственно у Supabase:

```http
POST https://PROJECT.supabase.co/auth/v1/token?grant_type=password
apikey: PUBLISHABLE_OR_ANON_KEY
Content-Type: application/json

{"email":"confirmed-test-user@your-domain.com","password":"test-password"}
```

Из ответа используется `access_token` в `Authorization: Bearer TOKEN`. Это поддерживаемый способ тестирования API данных; он не заменяет проверку cookie-входа/выхода.

## Заявки

### `GET /api/requests`

Cookie или Bearer обязательны. Параметры:

- `q`: подстрока названия, максимум 100 символов, необязательна;
- `status`: `Новая`, `В работе` или `Завершена`, необязателен;
- `page`: целое 1–10000, по умолчанию 1.

```json
{ "data": [], "total": 0, "page": 1, "pageSize": 20 }
```

`total` учитывает поиск, статус и владельца. Сортировка: сначала новые. В URL русские строки должны быть корректно URL-encoded.

### `POST /api/requests`

```json
{
  "id": "11111111-1111-4111-8111-111111111111",
  "title": "Бот для записи клиентов",
  "description": "Принимать заявки без ручного переноса",
  "category": "Бот"
}
```

Все четыре поля обязательны; UUID должен сохраняться клиентом при повторе одного создания. Владелец назначается сервером, статус `Новая` устанавливает база. `user_id`, `status`, служебные даты и любые другие поля отклоняются.

Первое создание: 201 `{data: Request,replayed:false}`. Повтор того же ID с тем же содержимым: 200 `{data: Request,replayed:true}`. Конфликт содержимого: 409 `ID_CONFLICT`.

### `GET /api/requests/:id`

200 `{data: Request}` для собственной записи. Для отсутствующей или чужой заявки одинаковый 404 `NOT_FOUND`, чтобы не раскрывать её существование. Некорректный UUID: 400.

### `PATCH /api/requests/:id`

Разрешено любое непустое подмножество `title`, `description`, `category`, `status`.

```json
{ "status": "В работе", "description": "Уточнённая задача" }
```

200 `{data: Request}`. Пустой объект, неизвестные поля, пустые обязательные значения и неизвестные категории/статусы: 400. Чужая запись: 404. DELETE не реализован.

## Формат заявки

```json
{
  "id": "11111111-1111-4111-8111-111111111111",
  "user_id": "aaaaaaaa-aaaa-4aaa-8aaa-aaaaaaaaaaaa",
  "title": "Бот для записи клиентов",
  "description": "Принимать заявки без ручного переноса",
  "category": "Бот",
  "status": "Новая",
  "created_at": "2026-11-06T12:00:00.000Z",
  "updated_at": "2026-11-06T12:00:00.000Z"
}
```

## Ошибки

```json
{
  "error": "Проверьте заполненные поля",
  "code": "VALIDATION_ERROR",
  "fields": { "title": ["Укажите название"] }
}
```

| HTTP | Когда                                               |
| ---- | --------------------------------------------------- |
| 400  | Валидация / некорректный JSON / ошибка регистрации  |
| 401  | Нет сессии, недействительный Bearer, неудачный вход |
| 403  | Origin другого сайта                                |
| 404  | Чужая или отсутствующая заявка                      |
| 409  | Конфликт ID при повторном создании                  |
| 413  | JSON больше 32 KiB                                  |
| 415  | Неподдерживаемый Content-Type                       |
| 429  | Лимит Supabase Auth                                 |
| 500  | Непредвиденная ошибка приложения                    |
| 502  | Ошибка операции с Supabase                          |
| 503  | Не настроено подключение                            |

При ненастроенном Supabase защищённые методы возвращают 503 до проверки данных заявки; сначала нужно выполнить настройку. Внутренние SQL-ошибки и stack trace клиенту не передаются.
