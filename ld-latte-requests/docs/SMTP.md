# SMTP для писем подтверждения

Подтверждение email временно отключено пользователем только в тестовом проекте для проверки приложения. Ниже — план возврата подтверждения: собственный SMTP нужен, чтобы отправка писем не зависела от ограничений встроенного почтового сервиса Supabase.

В журнале Auth проекта 6 ноября 2026 года зарегистрирован `over_email_send_rate_limit` на `/signup`. Это лимит отправки писем, а не ошибка Origin и не ошибка пароля. Повторная отправка формы не устраняет причину. Также встроенный почтовый сервис ограничивает круг получателей; одного ожидания может оказаться недостаточно.

## Что подготовить

- SMTP host и port от выбранного провайдера.
- SMTP username и отдельный SMTP password/API key.
- Подтверждённый у провайдера адрес отправителя или домен с настроенными DNS-записями.
- Имя отправителя: `LD LATTE`.

SMTP-секрет вводится в панели Supabase. Не добавляйте его в `NEXT_PUBLIC_*`, репозиторий, Postman-окружение или сообщения чата. Supabase отправляет письма самостоятельно: веб-приложению SMTP-секрет не нужен.

## Подключение

### Вариант для небольшого тестового проекта: Mail.ru

Если собственного домена нет, можно попробовать отправку через отдельный ящик Mail.ru. Это вариант для демонстрации с небольшим числом писем; доставку из Supabase нужно проверить после подключения. Действуют ограничения и антиспам-правила почтового провайдера.

В настройках Mail откройте Безопасность → Пароли для внешних приложений. Самостоятельно создайте пароль с названием `LD LATTE Supabase` и типом доступа **Только отправка писем в Почте**. Основной пароль от почты для SMTP не используется. Ввод нового пароля и его передачу в Supabase выполняет владелец аккаунта.

| Поле Supabase | Значение                                                 |
| ------------- | -------------------------------------------------------- |
| Sender email  | Полный адрес выделенного ящика Mail.ru                   |
| Sender name   | `LD LATTE`                                               |
| Host          | `smtp.mail.ru`                                           |
| Port          | `465` (SSL/TLS)                                          |
| Username      | Тот же полный адрес ящика                                |
| Password      | Отдельный пароль приложения с доступом только к отправке |

SMTP-секрет вводится непосредственно в Supabase, а не в `.env.local`. После сохранения пользователь запускает регистрацию на контролируемый адрес; проверяем письмо, подтверждение и вход.

Официальная инструкция: [пароль приложения и SMTP-параметры Mail](https://help.mail.ru/mail/login/mailer/).

### Вариант со своим доменом: Resend

Resend предоставляет [отдельную инструкцию подключения к Supabase](https://resend.com/docs/send-with-supabase-smtp). Для этого варианта нужны подтверждённый домен и API key. В Supabase указываются `smtp.resend.com`, порт `465`, username `resend` и API key в поле SMTP password. Sender email должен относиться к подтверждённому домену.

### Общий порядок

1. В панели выбранного почтового сервиса подтвердите адрес/домен отправителя и получите SMTP-параметры.
2. В проекте Supabase откройте Authentication → Email → SMTP settings (название раздела зависит от версии панели).
3. Включите Custom SMTP и заполните From address, sender name, host, port, username и SMTP password.
4. Оставьте Confirm email включённым.
5. В Authentication → URL Configuration установите Site URL для текущей среды. Для локального проекта используйте `http://127.0.0.1:3000`, для опубликованного — его HTTPS-адрес.
6. Проверьте Auth → Rate Limits. Лимит Supabase и лимит провайдера независимы; значение выбирается в пределах тарифа и назначения сервиса.
7. Выполните одну регистрацию на контролируемый адрес, проверьте доставку письма, подтверждение и вход. Затем подготовьте второго пользователя и запускайте интеграционную коллекцию с существующими аккаунтами.

Не используйте SQL-вставки в служебные таблицы Auth как замену штатной регистрации. При ошибке доставки проверьте точный код в Auth Logs и журнал почтового провайдера, не повторяйте регистрацию непрерывно.

Официальные источники: [Custom SMTP](https://supabase.com/docs/guides/auth/auth-smtp), [проверка Auth-процессов](https://supabase.com/docs/guides/auth/testing-auth-flows).
