# LD LATTE · заявки на автоматизацию

Веб-сервис по задаче №3 тестового задания: регистрация, вход/выход, создание и редактирование своих заявок, статусы, поиск и фильтр. Next.js App Router + TypeScript + Supabase Auth/PostgreSQL. Интерфейс на русском, рассчитан на компьютер и телефон.

## Текущее состояние

Полное сопоставление с критериями исходного PDF и оставшиеся шаги сдачи: [аудит ТЗ](docs/TZ-AUDIT.md). Публичное приложение и внешний Git-репозиторий пока не опубликованы.

Проект Supabase `Test LD LATTE` подключён через локальный `.env.local`. Миграции применены, политики RLS и права колонок проверены. Полный Postman-прогон: **50 запросов, 107 успешных проверок, 0 ошибок**. В браузере проверены создание и изменение заявки, сохранность после обновления, поиск/фильтр, мобильная форма и изоляция двух пользователей. [Отчёт проверки](docs/VERIFICATION.md).

По согласованию с владельцем Confirm email временно выключен только в тестовом проекте. Новые аккаунты регистрируются без письма; JWT и RLS работают. Перед публичным запуском нужно настроить SMTP и вернуть подтверждение. Без переменных окружения приложение показывает экран первого подключения, а API возвращает `503 SETUP_REQUIRED`.

## Быстрый запуск

Нужны Node.js 22.12+ (проверено с 24.18), npm и отдельный тестовый проект Supabase.

```powershell
cd 'C:\Users\Глеб\Documents\Учеба\ld-latte-requests'
npm.cmd ci
if (-not (Test-Path .env.local)) { Copy-Item .env.example .env.local }
```

1. Создайте проект в [Supabase Dashboard](https://supabase.com/dashboard). Сохраните пароль базы у себя: приложение его не использует.
2. Для нового проекта в **SQL Editor** выполните весь файл `supabase/migrations/20261106131943_create_automation_requests.sql`. Он создаёт таблицу, индексы, ограничения, права колонок, RLS и триггер времени обновления. Миграция рассчитана на однократное применение к новой базе; повторно вслепую запускать её не нужно. В подключённом проекте эта миграция уже применена. Вторая миграция `20261106132305_restrict_rls_auto_enable_execution.sql` закрывает клиентский вызов существующей платформенной функции `public.rls_auto_enable()`; применять её отдельно следует только при наличии этой функции.
3. В настройках API проекта скопируйте **Project URL** и **publishable key** (или legacy `anon` key).
4. Заполните `.env.local`:

   ```dotenv
   NEXT_PUBLIC_SUPABASE_URL=https://PROJECT.supabase.co
   NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=YOUR_PUBLISHABLE_KEY
   ```

   `service_role`, secret key и пароль базы сюда не помещаются. Приложение всегда обращается к данным с правами вошедшего пользователя.

5. В настройках Auth включите Email/password. Для изолированного демонстрационного проекта можно отключить **Confirm email**, чтобы два тестовых пользователя регистрировались без писем. Если подтверждение включено, зарегистрируйтесь, подтвердите адрес по письму и затем войдите. В **URL Configuration** укажите Site URL `http://127.0.0.1:3000` для локальной разработки; после размещения укажите HTTPS-адрес приложения. Не отключайте подтверждение почты у уже используемого рабочего проекта ради тестов.
6. Запустите:

   ```powershell
   npm.cmd run dev
   ```

7. Откройте [локальное приложение](http://127.0.0.1:3000). После изменения `.env.local` перезапустите сервер.

## Размещение

Приложение рассчитано на обычный Next.js-хостинг: например, Vercel или Node.js-сервер. Загрузите исходники в свой Git-репозиторий, задайте две переменные окружения, выполните сборку и укажите HTTPS Site URL в Supabase. При использовании reverse proxy сохраняйте исходный host/protocol, чтобы проверка Origin совпадала с публичным адресом. При переходе на новый домен проверьте повторный вход и cookie-сессию.

Исходники опубликованы в [общем репозитории](https://github.com/Kasspier/ld-latte-test-automation/tree/review/all-tasks/ld-latte-requests). В нём находятся все три задания; репозиторий открыт для просмотра и скачивания по решению владельца и архивирован для режима только чтения. Работающий HTTPS-сайт: [https://ld-latte-requests-omega.vercel.app](https://ld-latte-requests-omega.vercel.app). Размещён на бесплатном Vercel Hobby из проверенной копии исходников. Автоматический Git-деплой пока не подключён: в Vercel отсутствует GitHub Login Connection. Для повторного размещения используйте API/CLI либо сначала настройте Git-интеграцию.

## Основные решения

- Заявки защищены RLS и правами колонок в PostgreSQL. Скрытие элементов интерфейса не используется как средство авторизации.
- Браузер работает с Next.js API через HttpOnly cookies. Bearer-токены поддерживаются на API данных и проверки сессии для Postman.
- Идентификатор владельца назначается сервером, статус новой заявки — базой. Клиент не может назначить другой начальный статус через прямой REST.
- Стабильный UUID и уникальный ключ защищают создание от повторного HTTP-запроса. Пока форма сохраняется, блокируется повторное действие.
- AI применялся при разработке; функции генерации текста внутри продукта ТЗ не требует.
